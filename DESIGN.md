# Design: Ritme

This document is the source of the visual direction. The rule followed: direction first, then components.
The anti-slop filter is active in **during** mode; the dial below is held from the first screen
to the last.

## Design Read

> Reading this as: a daily time instrument for students and workers who switch tabs often,
> with the visual language of a paper instrument (analog kitchen timer, measuring device),
> dial **ENERGY 1 / RHYTHM 2 / MOTION 1**.

The dial is kept low because PRD section 7 forbids raising it: motion near zero,
digits are not animated, one dominant thing per screen.

## Identity

- **Focal point:** the time digits. The only large element on screen.
- **Accents at key moments only:** the main button and the progress line. Otherwise ink on paper.
- **Identity motif:** the cycle segment strip (one segment per session), also used
  as the icon wordmark. The same on screen, in the tab title, and in the mini window.
- **Copy tone:** short, flat, concrete. Labels state the situation, they do not cheerlead.

The active palette = 2 neutrals (paper, ink) + 1 accent per phase. The three accent values are
phase roles, not three brand colors. The table above is generated by `scripts/check-tokens.mjs` straight
from `src/styles/tokens.css`, so the values in this document cannot drift from the CSS.
The light accent versions are deliberately darkened until paper text on top of them reaches 4.5:1
(`src/lib/contrast.test.ts` guards it).

`data-phase` on `<html>` swaps `--accent`, so a mode change is just one
300 ms background color transition, not a digit animation.

## Typography

At most two families, both self-hosted (latin subset, variable, one file per
family → offline and no third-party requests).

- **JetBrains Mono** (`--font-mono`): time digits and other changing numbers.
  Monospace gives fixed digit widths without relying on each system's `tabular-nums`
  support, and its technical flavor is small because it is used for digits only.
  `font-variant-numeric: tabular-nums` is set anyway.
  Size: `clamp(5.5rem, 21vw, 17rem)`.
- **Archivo** (`--font-sans`): all UI text. A 19th-century work grotesk, technical
  but warm; avoids agent defaults (Inter, Geist, Space Grotesk) and stays neutral
  for an interface.

Small labels (`.label`) are only for structural markers such as the app name and system
status, raised to `ink-muted`, not a thin gray that fails contrast.

## Shape and depth

- Radius: 2 px (small chips), 4 px (controls), 8 px (surfaces). No pill shapes.
- Shadows: zero by default. Surfaces lift through paper value changes and 1 px
  lines; if elevation is ever needed, only one element may have it.
- Large empty space is structure, not leftover: the digits are surrounded by air,
  controls are grouped small below them.

## Progress

A thin horizontal line the width of the viewport (2 px) + a segment strip for the cycle, one segment
per session. Not a ring, not a gradient, no shadow.

## Motion

Near zero. The only things that move: the background color change when the phase changes (300 ms,
`cubic-bezier(0.2, 0, 0, 1)`), hover/focus color transitions on controls, and the progress
line fill. Digits are not animated. `prefers-reduced-motion: reduce` disables
all durations.

## Accessibility

- Text contrast at least WCAG AA; target 7:1 for primary text.
- Every control is keyboard reachable, focus ring 2 px in the accent color with a 2 px offset.
- `aria-live` only for status changes (session start/finish/phase change), not every second.

## Deliberately not used

Purple-blue gradients, gradient text, glassmorphism, glow, progress rings, emoji or sparkle
icons, stacked rounded cards, soft shadows on everything, capsule badges above
headings, the Inter font, motivational copy, confetti, bouncy animations.
